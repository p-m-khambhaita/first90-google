## 1. Product Overview

**First90** is an agentic AI-powered app for early-career professionals — graduates, apprentices, and new hires — navigating their first 90 days at a company.

It is NOT a generic career coach, CV tool, or job-search assistant. It is tightly scoped to a single, universally painful moment: *starting a new job and not knowing where you stand or where you fit.*

### Core promise
> "Your AI mentor for the first 90 days. Figure out your role. Build your confidence. Find where you really fit."

### What it does for the user
1. **Survive and perform** — understand expectations, communicate clearly, manage workload, build early relationships.
2. **Discover role fit** — through structured experiments, shadowing, and strengths mapping, help the user find which internal role archetype (e.g. Data Analyst, Product Associate, CX, Ops) actually suits them — not just the one they were hired for.
3. **Build lasting confidence** — daily reflections, micro-actions, and communications coaching so they feel less alone and more in control.

### Who it is for
- Primary: graduates, apprentices, and new hires aged ~18–28 in their first 1–3 corporate roles.
- Secondary: anyone starting a new role internally (lateral move, promotion, department transfer).
- NOT for: senior hires, career changers looking externally, job seekers.

### Studio context
First90 is the flagship product of **KatalYst** — a micro-SaaS studio building AI tools for early professionals. KatalYst is a solo-founder operation at early stage. First90 is the first product.

## 2. The Three Phases

First90 replaces the generic "Learn → Contribute → Lead" framing with a more honest, early-career-appropriate structure:

| Phase | Days | Theme | Goal |
|---|---|---|---|
| **Orient & Observe** | 1–30 | Understand | Learn the team, map energising vs draining tasks, start a strengths profile |
| **Experiment & Explore** | 31–60 | Discover | Try stretch tasks, shadow people in other roles, have exploratory coffee chats |
| **Decide & Position** | 61–90 | Act | Compare fit, prepare manager development conversation, make a plan |

Each phase has:
- A set of **goals** (auto-generated by PathArchitect based on role archetype)
- **Success signals** (concrete indicators, e.g. "shadowed one cross-functional meeting", "submitted first independent piece of work")
- A set of **agent activities** appropriate to that phase
- A **fit-check** at day 45 and day 90 triggered by SignalScout

## 3. The Four AI Agents

All agents run via **Antigravity** (Google's agent orchestration framework, Gemini-native). Agents communicate via a shared Supabase state layer and an event bus. All agent outputs are **proposals** the user must accept — no silent mutations.

### 3.1 PathArchitect
- **Purpose:** Build and maintain the user's personalised 30-60-90 day plan.
- **Triggers:** Role setup (initial), weekly schedule, and when SignalScout detects persistent plan slippage.
- **Inputs:** `roles`, `plans`, `plan_phases`, `goals`, `check_ins` (recent), `role_archetypes`, `events`.
- **Outputs:** Proposed plan deltas saved to `suggestions` table (type: `plan_update`). On acceptance, updates `plans` and `goals`.
- **Behaviour:** Starts from a role-archetype template, then adapts weekly based on what the user has completed, skipped, or flagged as irrelevant. The first 30 days are more prescriptive (stabilise), days 31–60 introduce exploration tasks, days 61–90 shift toward reflection and positioning.
- **Key constraint:** Never auto-updates the plan without user approval.

### 3.2 ExperienceCoach
- **Purpose:** Run daily/3x-weekly check-ins and generate micro-actions.
- **Triggers:** Evening scheduler (push notification) or user-initiated from app.
- **Inputs:** Today's check-in (confidence score 1–10, energy score 1–10, free text, tags), recent check-in history, current plan tasks.
- **Outputs:** 1–3 micro-actions for tomorrow (saved to `suggestions`), patterns surfaced as plain-language insights.
- **Behaviour:** Detects recurring low confidence → suggests specific interventions. Detects completion streaks → positive reinforcement. Passes signal summary to SignalScout after each run.
- **Check-in prompt style:** Short, warm, never clinical. "How did today go? What felt good, what was hard?" — not a form.

### 3.3 CommsCoach
- **Purpose:** Help the user communicate more confidently and effectively.
- **Triggers:**
  - **On-demand:** User pastes a draft email/Slack/Teams message into the app.
  - **Proactive:** Orchestrator detects a "tough conversation" task is coming due (e.g. "ask to shadow data team", "request more responsibility") and pre-generates a script.
- **Inputs:** Draft message or conversation topic + context (who, relationship, goal), current plan phase, user tone preferences.
- **Outputs:** 2–3 message variants ("More confident", "More concise", "More senior-friendly") with bullet-point explanations of each change.
- **Tone modes:** Professional-warm, Concise-direct, Senior-peer, Friendly-junior.
- **Proactive scripts cover:** Coffee chat requests, shadowing requests, raising a development conversation with a manager, flagging a mistake professionally.

### 3.4 SignalScout
- **Purpose:** Background analytics agent. Spots patterns across check-ins and events, triggers other agents when needed.
- **Triggers:** Daily scheduler (lightweight), weekly scheduler (full analysis), and after every check-in is logged.
- **Inputs:** `check_ins` time series (confidence, energy, tags), `events` log, `plans` (completion rate, skipped tasks), `role_fit_scores`, `exploration_activities`.
- **Outputs:**
  - Calls to ExperienceCoach when persistent pattern detected
  - Calls to PathArchitect when plan is consistently off-track
  - Fit-check reflection prompts at day ~45 and ~90
  - Updated `role_fit_scores` per archetype based on energy tags and exploration results
- **Role-fit scoring logic:** Each archetype has "marker tasks". When the user tags a check-in with energy=high and a task maps to an archetype marker, that archetype's fit score increases. Scores are surfaced as a ranked plain-language list.

## 4. Tech Stack

### Frontend
- **Framework:** Expo SDK 54+ with React Native
- **Navigation:** Expo Router (file-based, native tabs)
- **State:** Zustand or React Query (TBD)
- **UI:** Custom design system (no Expo UI or RN Paper)
- **Push:** Expo Notifications (FCM + APNs)
- **Platforms:** iOS first, Android second, Expo Web as stretch

### Backend
- **Pattern:** BFF (Backend for Frontend)
- **Runtime:** Node.js + TypeScript
- **Framework:** Fastify or Next.js API routes (TBD)
- **Hosting:** Google Cloud Run

### Database & Auth
- **Provider:** Supabase
- **DB:** Postgres
- **Auth:** Supabase Auth (magic link + Google OAuth)
- **Storage:** Supabase Storage
- **Vector:** pgvector (optional, semantic search over check-ins)
- **RLS:** Enabled on all tables. `user_id = auth.uid()` policy on all rows.

### Agent Orchestration
- **Framework:** Antigravity (Google, Gemini-native)
- **Pattern:** Event-driven. Backend emits events → Antigravity loads Supabase state → calls agents → writes suggestions back to DB.

### LLMs
- **Claude (Anthropic):** Complex, long-context tasks — plan generation, detailed comms coaching, fit-check reflections.
- **Gemini (Google):** Fast, frequent, structured tasks — check-in analysis, micro-action generation, signal scoring.
- **On-device (edge):** Small quantised SLMs (2–4B, ExecuTorch) for sensitive journaling, quick rewrites, instant suggestions that must never leave the device.

### Privacy Architecture
- **Principle:** Sensitive data (reflections, journaling, personal notes) never leaves the device by default.
- **Privacy modes:**
  - *Private mode:* Everything on-device SLM. No data sent to any server.
  - *Standard mode (default):* On-device for sensitive short tasks, cloud LLM for complex planning with PII stripping + explicit user consent prompt before escalation.
- **PII stripping:** Names, company names, colleague names replaced with `[manager]`, `[company]`, `[colleague]` before any prompt is sent to Claude/Gemini.
- **Supabase:** Only stores structured data (scores, tags, plan state, events). Free-text reflections stored encrypted client-side or not synced unless user opts in.
- **User-facing promise:** "Your reflections stay on your device. We never train on your data. When you need deeper help, we ask before sending anything to the cloud."

## 5. Data Model

```sql
-- Users
users (id uuid PK, email text, full_name text, timezone text, created_at timestamptz, preferences jsonb)

-- A job/role the user holds
roles (id uuid PK, user_id uuid FK, company_name text, job_title text, start_date date,
       end_date date, archetype_id uuid FK, is_active bool)

-- The 30-60-90 plan for a role
plans (id uuid PK, role_id uuid FK, user_id uuid FK, created_at timestamptz, updated_at timestamptz, status text)

-- Phases within a plan
plan_phases (id uuid PK, plan_id uuid FK, phase_number int, name text,
             start_day int, end_day int, theme text, created_at timestamptz)

-- Goals within a phase
goals (id uuid PK, plan_phase_id uuid FK, title text, description text,
       success_signal text, status text, due_day int, created_at timestamptz)

-- Daily/weekly check-ins
check_ins (id uuid PK, user_id uuid FK, role_id uuid FK, date date,
           confidence_score int, energy_score int, free_text text,
           tags text[], created_at timestamptz)

-- Append-only event log
events (id uuid PK, user_id uuid FK, role_id uuid FK, event_type text,
        payload jsonb, created_at timestamptz)

-- Agent output proposals awaiting user acceptance
suggestions (id uuid PK, user_id uuid FK, role_id uuid FK, agent_name text,
             suggestion_type text, content jsonb, status text,
             created_at timestamptz, actioned_at timestamptz)

-- Role archetype library (public read)
role_archetypes (id uuid PK, name text, description text, typical_tasks text[],
                 energising_markers text[], draining_markers text[],
                 skills_developed text[], transition_paths text[])

-- Per-user fit scores per archetype (updated by SignalScout)
role_fit_scores (id uuid PK, user_id uuid FK, role_id uuid FK,
                 archetype_id uuid FK, score float, last_updated timestamptz)

-- Exploration activities tied to a candidate archetype
exploration_activities (id uuid PK, user_id uuid FK, role_id uuid FK,
                        archetype_id uuid FK, activity_type text, title text,
                        status text, scheduled_day int, completed_at timestamptz)
```

### RLS policies
- All user tables: `user_id = auth.uid()` on SELECT, INSERT, UPDATE, DELETE.
- `role_archetypes`: public read, no user_id filter.
- `events`: insert-only from backend service role; users can read their own.
- `suggestions`: users read their own; agents write via service role.

## 7. Validated Pain Points

- Early-career staff feel "stuck" in roles with no clear progression — UK study, People Management, 2026
- ~73% of Gen Z workers say they lack access to a mentor
- Internal mobility increases 1-year retention by 66–72%, strongest effect on Gen Z (LinkedIn Economic Graph, 2025)
- Most 30-60-90 day plan resources are static templates nobody keeps using after week 1
- Human career coaches cost £50–150/hr and are inaccessible to most early-career workers
- Gen Z trapped in jobs they've outgrown without visibility on internal options (Employment Hero UK, 2025)

## 8. Competitive Landscape

| Product | Focus | Gap vs First90 |
|---|---|---|
| Path AI | General career growth, goal tracking | No 90-day structure, no internal role-fit |
| Career Compass AI | CV, interview, job search | External focus only, no agentic plan |
| Rocky.ai | Professional development coaching | Broad, not early-career specific |
| Himalayas AI Coach | Career path discovery | No daily check-ins or agent-driven adaptation |
| Google Career Dreamer | Career exploration, skills mapping | Broad, no time-boxed plan or comms coaching |
| Generic 30-60-90 templates | Structured onboarding plans | Static documents, no AI, no adaptation |

**First90's differentiators:**
1. Time-boxed to the first 90 days in a specific role — not "your whole career"
2. Internal role-fit discovery — not "quit and find a new job elsewhere"
3. Agentic adaptation — the plan evolves based on how things are actually going
4. Privacy-first — sensitive reflections stay on device by default

## 9. Monetisation

### B2C (initial)
- **Free tier:** Role setup, basic 30-60-90 plan, daily check-ins, confidence tracking
- **Paid tier (~£8–15/month or ~£25–40 one-time 90-day bundle):**
  - Role-fit analysis and archetype scoring
  - Exploration tracks (coffee chat scripts, shadowing tasks)
  - Advanced CommsCoach (proactive scripts, tone variants)
  - Manager conversation preparation
  - Exportable "growth log" (shareable summary of the 90 days)

### B2B (later)
- Sell to employers, apprenticeship providers, and grad schemes as a lightweight internal mobility + early-career experience platform
- Per-seat annual pricing + onboarding fee
- Anonymised cohort insights dashboard for HR/People teams
- Pitch: "We increase early-talent retention by helping new hires find the right internal role before they leave to find it elsewhere"

## 10. Developer Notes

- All agent prompts must be version-controlled in `03-agents/` as part of the spec docs.
- Supabase migrations live in `supabase/migrations/`.
- Use conventional commits: `feat:`, `fix:`, `docs:`, `chore:`, `agent:`.
- Privacy is non-negotiable — any feature that processes free-text user input must document where it runs (on-device vs cloud) in its spec file.
- All agent outputs go via `suggestions` table — never apply changes to plans/goals directly.
- When in doubt about agent architecture: **supervised autonomy** — agents suggest, users decide.
- No localStorage or sessionStorage in the web layer (sandbox limitation). Use in-memory or Supabase for all state.
